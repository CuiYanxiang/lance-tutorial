Ray × Lance：算力与存储分工
示意 · Ray 负责「算」，Lance 负责「存」，Arrow 为公共内存表达
① 上游数据源
Parquet / Kafka / API / HF Hub
内存放不下 → 流式/分布式拉取
② Ray（分布式计算层）
· read_lance：columns 裁剪 + filter 下推
· map / batch inference：生成 embedding、特征
· add_columns：Ray UDF 并行回填新列
· compact_files：多 worker 压实碎片
· create_scalar_index：分布式建 FTS/BTREE/向量索引
③ Lance 数据集（湖仓层）
· Blob V2 + 向量 + 标量同表
· 版本 / time travel / tags
· MVCC + ACID 快照隔离
· schema 演进（加列不重写全表）
④ Serving（在线）
单机 pylance
take() / take_blobs() 低延迟随机点读
nearest / full_text 向量·全文检索
↑ write_lance（create/append）　↓ read_lance（投影+过滤下推）
最佳实践要点
过滤下推优先 → 减少 I/O write_lance 用 concurrency 限流 先压实再重建索引 tags 固定发布基线 serving 走单机 pylance 低延迟点读
