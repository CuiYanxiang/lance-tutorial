## 2.1 格式分层与 MVCC 语义

Lance = **文件格式 + 表格式 + catalog 规格**三合一：



* `.lance`**&#x20;数据文件**：列存，类比 Parquet，但额外做了行寻址（row addressing），让随机点读 1\~2 次 I/O 往返就能定位。

* **dataset 层**：由 manifest 维护的片段（fragment）集合，提供 **MVCC / ACID**：


  * 读：打开时读到某个 manifest 快照，**快照隔离**—— 别的写不影响正在进行的读。

  * 写：提交时原子地把 `_latest.manifest` 指到新 snapshot。写成功后才可见。

  * 并发：多写并发靠 manifest 乐观并发控制；写冲突时后者需重试（见运维篇）。

`data_storage_version` 决定新写数据文件的**编码格式**。它在 `create` / `overwrite` 时定下默认值；`append / update / merge_insert / compact` 可针对单次操作显式指定另一个 V2 子版本，**不重写其他文件**。



| 版本            | 关键能力                                                                              |
| ------------- | --------------------------------------------------------------------------------- |
| 2.0           | 基础列存 + 随机访问                                                                       |
| 2.1           | 结构编码（structural encoding），随机读 I/O 降到 1–2 次往返，文件更小更简单                              |
| **2.2（生产推荐）** | **Blob V2**（外部 blob、布局语义改进）+ **字典值压缩**（文本类数据较 Parquet 省约 50% 存储，且不拖慢访问路径）+ 灵活存储演进 |
| 2.3           | 实验态，不稳定，**仅实验**                                                                   |

> 实操纪律：
> 新建数据集固定 
>
> `data_storage_version="2.2"`
>
> 。
> 想单次升级某批文件可 
>
> `update(..., data_storage_version="2.2")`
>
>  / 
>
> `merge_insert(...).data_storage_version("2.2")`
>
>  / 
>
> `optimize.compact_files(data_storage_version="2.2")`
>
> 。
> **混版本读写前必须把所有 reader/writer 升级到「混版本感知」的发行版**
>
> ；老 writer 要 drain / 重启 /fencing。提交时会自动设置配套的读写 feature flag，老客户端不认识这些 flag 会拒绝读这个 snapshot。
> `V1`
>
>  和 
>
> `V2`
>
>  不能混用。

## 2.2 Merge Insert：批量同步的瑞士军刀

`update()` 适合「按条件改」；当你手里是一张**带主键的新表**要和旧表对齐**整行**，用 `merge_insert(主键列)`，内部是 hash join，比逐行 update 快几个量级。四种语义可组合：



```
import lance, pyarrow as pa
ds = lance.dataset("./alice.lance")

new = pa.Table.from_pylist([
    {"name": "Alice", "age": 30},
    {"name": "Carla", "age": 37},
])
```

**① 批量更新（命中即更新）**



```
ds.merge_insert("name").when_matched_update_all().execute(new)
```

**② 不存在才插入（幂等导入，防重复）**



```
ds.merge_insert("name").when_not_matched_insert_all().execute(new)
```

**③ Upsert（命中更新 / 未命中插入）**



```
ds.merge_insert("name") \
  .when_matched_update_all() \
  .when_not_matched_insert_all() \
  .execute(new)
```

**④ 按源数据替换一段区域（≈ 一个事务里 delete+insert）**



```
# 删除所有 age>=40 的旧行，再插入 new 里的行
ds.merge_insert("name") \
  .when_not_matched_insert_all() \
  .when_not_matched_by_source_delete("age >= 40") \
  .execute(new)
```

注意：被修改的行会被删了再插到表尾，内部 hash join 也会打乱相对顺序 ——**别拿 merge\_insert 当有序覆盖用**。

## 2.3 读路径：过滤下推的完整 SQL 方言

`filter=` 里写标准 SQL 谓词，Lance 直接下推到存储，显著减少 IO。支持：



* 比较：`> >= < <= =`；逻辑 `AND OR NOT`

* `IS NULL / IS NOT NULL`，`IS TRUE / IS FALSE` 系列

* `IN (...)`、`LIKE / NOT LIKE`、`regexp_match(col, 'pat')`、`CAST`

**嵌套字段**：struct 用字段名下标，list 用序号下标：



```
filter="((label IN [10,20]) AND (note['email'] IS NOT NULL)) OR NOT note['created']"
```

列名含空格或保留字用反引号，且嵌套每一段都要包：



```
filter="`CUBE` = 10 AND `with space`.`inner space` < 2"
```

> 列名
>
> **不能含&#x20;**
>
> `.`
>
> 。日期 / 时间 / 字面量带类型前缀：
>
> `date_col = date '2021-01-01'`
>
> 、
>
> `ts = timestamp(3) '2021-01-01 00:00:00'`
>
> 。

SQL→Arrow 类型映射（写 &#x60;CAST` 时对照）：`int/integer`→Int32，`bigint`→Int64，`float`→Float32，`double`→Float64，`decimal(p,s)`→Decimal128，`date`→Date32，`string`→Utf8，`binary`→Binary。

## 2.4 Schema 演进：加列不重写全表

传统数仓加列常要整表重写。Lance 的「加列带数据」本质是**写新文件**：



```
import lance
ds = lance.dataset("./docs.lance")

@lance.batch_udf()
def add_embeddings(batch):
    vecs = model.encode(batch["text"])     # 你自己的 embedder
    return {"embedding": vecs}

ds.add_columns(add_embeddings)              # 只写新增列的数据文件，不重写旧列
```

也支持改名、改类型、加空列、删列（schema evolution 的其他形式）。这是「data evolution > schema evolution」主张的落地：回填历史数据和加列是同一件便宜事。

## 2.5 索引：IVF-PQ 向量 + FTS + 标量索引

> ⚠️ 
>
> **两个实测必踩的坑**
>
> （pylance 13）：
> **向量列必须是定长&#x20;**
>
> `FixedSizeList`
>
> ，不能是 Python list 默认推出来的变长 
>
> `list<double>`
>
> 。建表时显式指定类型：
>

```
vec_type = pa.list_(pa.float32(), 16)   # 16 维定长
table = pa.table({"id": ids, "vector": pa.array(vecs, type=vec_type)})
```

> **向量索引用&#x20;**
>
> `create_index`
>
> **；标量 / 全文索引用另一个方法&#x20;**
>
> `create_scalar_index`
>
> 。
>
> `create_index`
>
>  只接受向量列，传字符串列会报「Vector column must be FixedSizeList」。

### 向量近似最近邻（ANN）



```
ds.create_index(
    "vector",                       # 向量列（必须是 FixedSizeList）
    index_type="IVF_PQ",
    metric="cosine",                # "L2"(=euclidean, 默认) / "cosine" / "dot"
    num_partitions=256,              # IVF 聚类簇数（≈ nlist）
    num_sub_vectors=16,              # PQ 子向量数（决定压缩比，常取 dim 的因数）
)
```

可选向量索引族：`IVF_PQ`、`IVF_HNSW_PQ`、`IVF_HNSW_SQ`。

调参经验（和业界 IVF-PQ 一致）：



* `num_partitions` ≈ `sqrt(N)` 量级起调；查询时用 `nprobes` 决定扫几个簇 ——`nprobes` 越大越准越慢。

* `num_sub_vectors` 通常是向量维度的因数（如 1024 维 → 96/128）。越大越准、索引越大。

* Linux + NVIDIA 可加 `accelerator="cuda"` 用 GPU 建索引（大数据集建库加速明显）。

### 标量 / 全文索引

标量索引用 `create_scalar_index`（不是 `create_index`），支持的 `index_type`：

`BTREE`（高基数列最常用）、`BITMAP`（低基数 / 标签）、`LABEL_LIST`、`NGRAM`、`ZONEMAP`、`BLOOMFILTER`、`RTREE`，以及全文的 `INVERTED`**&#x20;/&#x20;**`FTS`（BM25）。



```
ds.create_scalar_index("category", index_type="BTREE")
ds.create_scalar_index("text", index_type="INVERTED")   # BM25 全文
```

### 混合检索（同一个数据集，三种查询）



```
# ① 纯向量 KNN
ds.to_table(nearest={"column": "vector", "q": query_vec, "k": 10})

# ② 向量 + 标量过滤（先过滤再/后ANN，Lance 优化器自动选路）
ds.to_table(nearest={"column": "vector", "q": query_vec, "k": 10},
            filter="year > 2020")

# ③ 全文检索（BM25）
ds.to_table(full_text_query="machine learning")
```

> 注意：
>
> **压实（compact）会让被重写片段上的旧索引失效**
>
> 。官方建议顺序：先压实重排文件，再重建索引。

## 2.6 Blob V2：图片 / 视频 / 音频当一等公民

大二进制（blob）懒加载，不必把整个字节塞进列里：



```
import lance, av
ds = lance.dataset("s3://bucket/videos.lance")

blobs = ds.take_blobs("video", ids=[2, 51])   # 只取这两行的 blob 字节
for b in blobs:
    with av.open(b) as c:
        stream = c.streams.video[0]
        c.seek(start_time=500, stream=stream)
```

Blob V2（2.2 引入）把大对象外置 + 布局语义改进，随机 blob 读取相对整 row-group 解码快数十倍 —— 这是它做多模态训练集的基础（实战篇 PyTorch 例子）。

## 2.7 对象存储与多 base 布局



```
ds = lance.dataset("s3://my-bucket/path/data.lance",
                   storage_options={"aws_region": "us-east-1"})
```



* 支持 `s3://`、`gs://`，以及 HuggingFace Hub 的 `hf://datasets/.../train.lance`。

* **多 base 布局**：一张表的数据文件可分散在多个 bucket / 路径，建表时注册额外 base：



```
lance.write_dataset(data, "s3://bucket-1/my_dataset",
                    initial_bases=["s3://other-bucket/prefix"])
```

适合跨 bucket 归档、冷热分离。



* 写路径若要自动清理旧版本，writer 需要有对象存储的 **delete 权限**（运维篇会用到）。

## 2.8 版本管理：像 Git 一样管理数据集



```
import lance
ds = lance.dataset("./tags.lance")

ds.versions()                       # 列出所有历史版本
ds.checkout_version(1)             # 时间旅行：读第 1 版快照
```

### Tags（给版本打标签，不产生新版本）



```
ds.tags.create("v1-prod", (None, 1))     # 给 main 分支第 1 版打标签
ds.tags.create("train-v1", ds.version)     # 标签指向当前版
ds.tags.list(); ds.tags.list_ordered()
ds.tags.update("v1-prod", (None, 2))
ds.tags.delete("v1-prod")
```

> **打了 tag 的版本不会被&#x20;**
>
> `cleanup_old_versions`
>
> **&#x20;回收**
>
> 。想彻底删，先 
>
> `tags.delete()`
>
> 。这正是「模型训练基线」要长期保留的机制。

### Branches（并行演化线，各自版本历史）



```
ds.create_branch("experiment")                       # 从当前版拉分支
lance.write_dataset(new_data, "experiment", mode="append")   # 在分支上写
ds.tags.create("exp-rc", ("experiment", None))         # 分支最新版打标签
exp = ds.checkout_version(("experiment", None))        # 读分支最新版
ds.branches.list(); ds.branches.delete("experiment") # 删分支才允许回收其引用文件
```

`reference` 参数四态：整数（当前分支第几版）、字符串（tag 名）、`(None, n)`（main 第 n 版）、`("branch", n|None)`（指定分支）。`main` 是保留的默认分支名。

### Shallow clone（浅克隆）

从某个版本 /tag 派生一个不复制数据的新数据集，适合「Git for AI Data」式的实验分支 —— 详见官方 branching 文档。
