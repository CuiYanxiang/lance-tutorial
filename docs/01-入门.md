## 1.1 先建立正确心智模型

很多人第一次把 Lance 当成「更快的 Parquet」，这只对了一半。Lance 同时是：



* **一种文件格式**：你写出来的是一堆 `.lance` 列存文件，内部按列组织，随机寻址快。

* **一张有历史的表**：每次写操作都生成一个新的 **version（快照）**，写不删旧文件 —— 靠 manifest 指向当前版本。这和 Iceberg 的 snapshot、Git 的 commit 是同一个思路。

所以记住两条铁律：



1. **不可变（immutable）**：数据文件一旦写出就不改。更新 = 写新文件 + 换一个 manifest 指过去。

2. **每次写都产生新版本**：`insert / append / update / delete / merge_insert / compact / 建索引` 全都会 +1 版本。改完要**重新&#x20;**`lance.dataset()`**&#x20;打开**才看得到（同一个 `ds` 对象不自动刷新）。

## 1.2 写出第一个数据集

`lance.write_dataset` 接受 `pyarrow.Table`、`pandas.DataFrame`、`pyarrow.dataset.Dataset`、或 `Iterator[pa.RecordBatch]`（流式）。



```
import lance, pyarrow as pa

table = pa.Table.from_pylist([
    {"name": "Alice", "age": 20},
    {"name": "Bob",   "age": 30},
])
ds = lance.write_dataset(
    table,
    "./alice.lance",
    data_storage_version="2.2",   # 生产默认；实验才用 "2.3"
)
print(ds.version, ds.count_rows())   # 1  2
```

**内存放不下时用流式写入**（给一个 `RecordBatch` 迭代器 + 显式 schema）：



```
from typing import Iterator

def producer() -> Iterator[pa.RecordBatch]:
    yield pa.RecordBatch.from_pylist([{"name": "Alice", "age": 20}])
    yield pa.RecordBatch.from_pylist([{"name": "Bob",   "age": 30}])

schema = pa.schema([("name", pa.string()), ("age", pa.int32())])
ds = lance.write_dataset(producer(), "./alice.lance", schema=schema, mode="overwrite")
```

## 1.3 打开与读取



```
ds = lance.dataset("./alice.lance")          # 本地；也支持 s3:// / gs:// / hf://
```

**全量读进内存**：`ds.to_table()` → 一个 `pyarrow.Table`，再 `.to_pandas()`。

**但真正发挥 Lance 威力的是「只读需要的」**—— 列裁剪（projection）+ 过滤下推（predicate pushdown）：



```
tbl = ds.to_table(
    columns=["name"],                 # 只读 name 列，age 的磁盘 IO 直接省掉
    filter="age >= 25 AND name IS NOT NULL",
    limit=1000, offset=0,
)
print(tbl.to_pandas())
```

**太大读不下就分批流式读**：



```
for batch in ds.to_batches(columns=["name"], filter="age >= 18"):
    ...  # 每个 batch 是 pa.RecordBatch
```

**随机取行（Lance 相对 Parquet 的核心优势）**：



```
ds.take([1, 100, 500], columns=["name"])   # 直接取第 2/101/501 行，不用扫全表
ds.sample(1000, columns=["name"])          # 随机采样 1000 行 —— ML shuffle/采样的基础
```

> 为什么随机读快：Parquet 按 row-group 组织，随机读一行往往要解码整个 row-group；Lance 有独立的行寻址 + 二级索引，官方实测随机访问比 Parquet/Iceberg 快约 100×。这正是它适合 ML serving、交互式采样的原因。

## 1.4 增、删、改

### 追加（insert /append）



```
new = pa.Table.from_pylist([{"name": "Carla", "age": 37}])
ds.insert(new)                                   # 方式一
ds = lance.write_dataset(new, ds, mode="append") # 方式二：把 dataset 路径当目标
```

`mode` 取值：`"create"`（默认，已存在报错）、`"overwrite"`（覆盖重建）、`"append"`（追加）。

### 删除（按 SQL 条件软删）



```
ds.delete("name = 'Bob'")
```

注意：**不是真的删文件**。Lance 写一个很小的「删除索引」文件把这些行标记为已删，扫描时跳过。好处：快、且不会让引用这些文件的索引失效。代价：删得多了会拖慢扫描 —— 这是运维篇要压实清理的伏笔。

### 更新（按 SQL 表达式）



```
# update 的值是 SQL 表达式，所以字符串常量要加单引号
ds.update({"name": "'Robert'"}, where="name = 'Bob'")
ds.update({"age": "age + 2"})          # 引用现有列做计算
```

要批量按主键替换多行时，逐行 `update` 很慢 —— 那是精通篇 `merge_insert` 的地盘。

## 1.5 看懂 `.lance` 目录里到底有什么

建一次、追加两次后 `ls -R alice.lance` 大致长这样：



```
alice.lance/
├── _versions/
│   ├── 1.version          # 第 1 版 manifest：指向创建时的数据文件
│   ├── 2.version          # 第 2 版：追加后
│   └── 3.version          # 第 3 版：删除后
├── data/
│   ├── 0-0-...lance       # 数据片段（fragment）
│   ├── 1-0-...lance
│   └── _deletion/         # 软删标记文件（如果有 delete）
└── _latest.manifest       # 指针：当前最新是第几版
```

要点：



* `_versions/*.version` 是**快照清单**，记录这一版引用了哪些数据文件、schema 是什么。

* 数据文件写进去就不动；新版本只是**引用了同一批 + 新增的文件**。

* 所以磁盘会随着每次写**只增不减**—— 旧版本还在引用旧文件。想回收空间，必须显式清理（运维篇）。
