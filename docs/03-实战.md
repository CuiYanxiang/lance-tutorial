## 实战 1：把数仓里的 Parquet 批量迁成 Lance

**场景**：你有一批 Parquet 表（历史数仓），想切到 Lance 获得随机访问 + 版本 + 内建向量检索。



```
import lance, pyarrow.dataset as ds, pyarrow.parquet as pq

def parquet_to_lance(parquet_path: str, lance_path: str):
    pq_ds = ds.dataset(parquet_path, format="parquet")   # 支持目录/通配
    tbl = pq_ds.to_table()                               # 数据大可分批
    lance.write_dataset(
        tbl, lance_path,
        data_storage_version="2.2",
        mode="overwrite",
    )
    # 验证
    back = lance.dataset(lance_path)
    assert back.count_rows() == pq_ds.count_rows()
    print("rows:", back.count_rows())
```

**点评**：



* 一行 `write_dataset(arrow_table, ...)` 即完成转换，官方卖点就是「1 行转 Parquet→Lance」。

* 迁完别丢原 Parquet—— 先双写 / 并行跑一个迭代期，确认查询与训练无回归再下线。

* 有大 blob 列（图片字节）时，迁到 2.2 后可考虑改成 Blob V2 外置，省存储。

## 实战 2：多模态训练集（图片 + embedding 同表）喂给 PyTorch

**场景**：图文对数据集，随机取样、shuffle、按 batch 取图。



```
import lance, torch
from torch.utils.data import Dataset, DataLoader

class LanceImageDataset(Dataset):
    def __init__(self, uri):
        self.ds = lance.dataset(uri)
    def __len__(self):
        return self.ds.count_rows()
    def __getitem__(self, idx):
        row = self.ds.take([idx], columns=["image", "label", "embedding"]).to_pylist()[0]
        img = decode_image_bytes(row["image"])          # 你的解码
        return torch.tensor(row["embedding"]), row["label"]

# 训练时：Lance 的随机访问让 __getitem__(random_idx) 飞快
loader = DataLoader(LanceImageDataset("s3://bucket/train.lance"),
                    batch_size=64, shuffle=True, num_workers=4)
```

**点评**：



* 传统方案里图片存磁盘、标签存 Parquet，要维护两套路径映射；Lance 把 blob 懒加载进同一张表，`take([i])` 一次拿到行内所有列。

* `take_blobs("image", ids=[...])` 比逐行 take 更省，批量取 blob 时优先用它。

* 大规模训练配合 `sample()` 做 epoch 内随机子集。

## 实战 3：RAG 向量检索库（embedding + FTS + 混合）

**场景**：文档切块后存 Lance，建向量索引 + BM25，做 hybrid retrieval。



```
import lance, pyarrow as pa

# 1) 写入：text + embedding
rows = [{"id": i, "text": chunk, "embedding": embed(chunk)}
        for i, chunk in enumerate(chunks)]
ds = lance.write_dataset(pa.Table.from_pylist(rows), "./rag.lance",
                         data_storage_version="2.2")

# 2) 建索引：向量 IVF-PQ（create_index）+ 全文倒排（create_scalar_index）
ds.create_index("embedding", index_type="IVF_PQ", metric="cosine",
                num_partitions=256, num_sub_vectors=96)
ds.create_scalar_index("text", index_type="INVERTED")   # FTS/BM25

# 3) 查询
q_vec = embed("用户问题")
vec_hits = ds.to_table(nearest={"column": "embedding", "q": q_vec, "k": 10},
                       filter="length(text) > 50").to_pandas()
kw_hits  = ds.to_table(full_text_query="用户问题关键词").to_pandas()
# 两路召回后在应用层做 RRF 融合
```

**点评**：



* 这正是 LanceDB 的底层能力；用裸 `lance` 也能搭出轻量 RAG，无需额外数据库进程。

* `num_partitions` 按数据量调（≈√N）；`num_sub_vectors` 取维度因数。

* hybrid 融合建议在应用层做 RRF，比硬塞一个查询更可控。

## 实战 4：和 DuckDB / Spark 互通（不换引擎也能查 Lance）

**场景**：已经有 SQL 分析栈，不想离开 DuckDB/Spark 就能查 Lance。



```
# DuckDB：直接 attach / 扫描 Lance（DuckDB 2026 已原生 test-driving Lance）
# duckdb>  SELECT * FROM 's3://bucket/train.lance' WHERE age > 18;
# 或 ATTACH 为表后写标准 SQL。

# Spark：用 Lance 的 Spark connector 把 Lance 当数据源读写
# spark.read.format("lance").load("s3://bucket/train.lance")
```

**点评**：



* Lance 以 Apache Arrow 为内存表达，和 Pandas/Polars/Ray/DuckDB/DataFusion/Spark/Trino/Flink 都是同一种「语言」，互通成本极低。

* 实践建议：**训练 / 随机访问走 Lance 原生 API，重 SQL 批量分析走 DuckDB/Spark**，同一份数据不搬运。

## 实战 5：在 HuggingFace Hub 上分发 / 拉取多模态数据集

**场景**：把数据集发到 HF Hub 共享，或直接流式拉取别人的 Lance 数据集。



```
import lance

# 拉取 HF Hub 上的 Lance 数据集（无需先下载，直接流式扫）
ds = lance.dataset("hf://datasets/lance-format/laion-1m/data/train.lance")
print(ds.to_table(filter="width > 512", columns=["caption"], limit=5).to_pandas())
```

**点评**：



* Lance 已被 HF Hub 原生支持：scalar + blob + embedding + 索引打包在一份资产里，分享即「一个数据集 + 可直接过滤查询」。

* 上传时每个写事务（含建索引）都会产生新版本，和 tag 配合可发布 `v1` 稳定快照。
